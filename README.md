# Aushadhi Pharma — Production Website Starter

This package is the production-oriented foundation for the Aushadhi Pharma wholesale medicine website.

## What is now included

- Server-side SQLite database
- Secure password hashing with bcrypt
- HTTP-only authentication cookie
- Admin and retailer roles
- Retailer registration/login
- Product catalogue backed by the database
- Admin product management: add, edit, soft-delete
- Admin image upload (JPG/PNG/WEBP, max 5 MB)
- Product fields: name, salt/composition, category, packing, MRP, wholesale rate, scheme, MOQ, stock, HSN, GST rate and image
- Server-side order validation and order storage
- Admin order status management
- Retailer order history
- Admin retailer list
- Rate limiting + Helmet security headers
- Responsive mobile/desktop UI
- Livonac-Zyme-DS 225 ml sample product loaded from the provided product images

## IMPORTANT: this is not deployed yet

The code is ready to be connected to a real hosting/server environment, but it is **not a claim that the live website is already online**.

Before public launch:

1. Set a strong random `JWT_SECRET`.
2. Set a strong `ADMIN_USERNAME` and `ADMIN_PASSWORD` in `.env`.
3. Run behind HTTPS.
4. Configure regular database backups.
5. Verify all business/legal information before publishing it.
6. Add your real medicine catalogue and actual wholesale rates.
7. Review GST/HSN/invoice requirements with the business's accountant/compliance professional.
8. Consider PostgreSQL instead of SQLite if the site will have substantial concurrent traffic.

## Run locally

```bash
cp .env.example .env
npm install
npm start
```

Open `http://localhost:3000`.

## Admin

Open **Admin** from the navigation and use the credentials configured in `.env`.

Do not use a shared/default admin password on a public server.

## Adding a medicine from Admin

Admin → Products → Add Product

You can enter:
- Product name
- Salt/composition
- Category
- Packing
- MRP
- Wholesale rate
- MOQ
- Stock
- HSN
- GST rate
- Scheme
- Product image

The image is uploaded to the server and the product record stores its URL.


## Render deployment (GitHub-ready)

1. Create a new GitHub repository and upload this folder's contents.
2. In Render choose **New → Web Service** and connect the GitHub repository.
3. Render can use the included `render.yaml`, or set Build Command to `npm install` and Start Command to `npm start`.
4. Add `ADMIN_USERNAME` and a strong `ADMIN_PASSWORD` as secret environment variables. `JWT_SECRET` is generated by Render when using the blueprint.
5. Deploy and open the generated `onrender.com` URL.

### Important for testing
This starter uses SQLite. Render's free web-service filesystem is not a suitable permanent database for a real wholesale business: data can be lost when the service is redeployed/restarted. For production, migrate the database to PostgreSQL (for example Supabase) and use durable object storage for product images.

Never put passwords, API keys, database URLs, or `.env` files into GitHub.
